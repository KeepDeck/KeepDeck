Пункт 6 — контракт неполноты

Первый пункт ступени 1, разобранный до строк. Всё прочитано на HEAD 02be0fd6.

Что он делает

Даёт ответам плагина место, где сказать: «я отдал меньше, чем есть». Сегодня такого места нет — describe отдаёт факты без признака неполноты, transcript отдаёт массив ходов, content отдаёт голую строку. Пункт 6 сам по себе ничего не чинит и пользователю не виден: он делает возможными пункты 1 и 4.

Формы

// packages/plugin-api/src/context/agents.ts

/** Почему ответ короче, чем существует. kind называет меру:
 *  файл меряется байтами, разговор — ходами. */
export type Shortfall =
  | { kind: "bytes";  size: number;   readBytes: number }
  | { kind: "turns";  total: number;  returned: number }
  | { kind: "parts";  unreadableParts: number };

export interface AgentSessionFacts {
  cwd: string;
  title?: string;
  transcriptPath?: string;
  /** О ТОМ чтении, которое сделал этот describe. Отсутствует —
   *  значит это чтение ничего не недодало ЛИБО молчит о том,
   *  чего не делало (быстрая дорожка тела не читает). */
  shortfall?: Shortfall[];
}

export interface AgentHistory {
  // …list / listing? / describe / content / transcript без изменений…

  /** Страница транскрипта С признаком неполноты. Старый
   *  transcript() остаётся честным сам по себе — два честных
   *  контракта, а не старый и его замена. */
  transcriptPage?(
    ref: string,
    page: { offset: number; limit: number },
  ): Promise<{ entries: AgentTranscriptEntry[]; shortfall?: Shortfall[] }>;
}

// В плагине — ОДНА реализация, старый метод её распаковывает:
//   const readPage = async (ref, page) => { …вся работа… };
//   transcriptPage: readPage,
//   transcript: async (ref, page) => (await readPage(ref, page)).entries,
// Разойтись они не могут: второй выведен из первого.

Массив, а не одиночка — одно чтение несёт два рода разом: у opencode в одном вызове content() цикл роняет нечитаемые части и упирается в потолок.

Пустой массив запрещён — [] была бы вторая орфография полноты. Присутствует значит минимум один элемент.

Без complete — у listing() он уместен, потому что перечисление бинарно; здесь он выводится из shortfall и стал бы второй правдой об одном.

Ловушка: компилятор здесь не поможет

Потребитель транскрипта вызывает метод через приведение типа, а не через интерфейс:

// src/app/useSessionsBrowser.ts:123-130
return (contribution.entry.history as {
  transcript(ref: string, page: {offset: number; limit: number}):
    Promise<AgentTranscriptEntry[]>;
}).transcript(ref, { offset, limit });

Приведение отсекает интерфейс. Если добавить transcriptPage и забыть научить это место — tsc промолчит, просмотрщик тихо продолжит звать старый метод, и вся работа не доедет до экрана, не сломав ни одной сборки. Значит здесь нужен тест, а не типы: «плагин объявляет transcriptPage → браузер зовёт именно его».

Вторая ловушка: шовный пин слеп

В шве уже есть тест, который прогоняет describe через границу и сверяет ответ целиком:

// src/plugins/external/rpc/hostDispatch.test.ts:290-294
await expect(describe).resolves.toEqual({
  cwd: "/repo", title: "Session", transcriptPath: "/transcript",
});

Кажется, что он и защищает границу. Не защищает: если санитайзер срежет новое поле, сравнение всё равно пройдёт — toEqual не замечает отсутствия необязательного поля. Тест зелёный, метка молча срезана, работа не доехала. Значит свидетель «санитайзер пропускает метку» — не один из списка, а единственный страж этой границы, и написан он должен быть так, чтобы сперва покраснеть на срезе, а не просто зафиксировать итоговую форму.

Проверка на дублирование

План в первой редакции размазывал логику в трёх местах. Кодовая база уже обжигалась на этом: комментарий plugin-api/context/historyText.ts говорит прямо — «две частные копии эвристики заголовка уже разошлись», и модуль построен как их общий дом. Туда же идут наши помощники.

Что размазывалосьКак лечится
Третье почти-одинаковое тело в каждом плагине. Сегодня content и transcript уже близнецы: то же чтение, тот же разбор, разный хвост. Отдельная реализация transcriptPage дала бы третью копию ×4 плагина.Работа делается один раз; старый transcript — однострочная распаковка нового. Два контракта тогда не могут разойтись по построению, а не «пока их держат синхронными».
Сборка {kind:"bytes"} втройне — claude, codex, kimi делают один и тот же шаг из truncated и size.Один помощник в historyText.ts. Туда же правило «пустого массива не бывает»: иначе оно живёт в четырёх плагинах и в санитайзере, а так — в помощнике и на границе (границе доверять нельзя всё равно).
Формулировка строки журнала ×4 — каждый плагин сочиняет свою.Один форматтер из Shortfall[]. Иначе выверенные слова разойдутся за неделю — тот же род, что уже случился с заголовком.
Сам вызов журнала ×4 — форматтер убирает расхождение слов, но if (shortfall?.length) log.warn(…) повторится в каждом плагине: тот же род этажом выше.Помощник принимает журнал, метку сессии и Shortfall[] — слова и вызов живут ровно один раз.

Где чему жить. Граница проходит по вопросу «зовёт ли это хост», а не «есть ли уже рантайм в файле». Shortfall — контракт, его читают обе стороны провода, он остаётся в agents.ts. Сборка метки из прочитанного файла и строка журнала — поведение плагинной стороны, хост их не зовёт никогда: их дом historyText.ts, чья шапка ровно про общее поведение парсеров истории.

Оговорка, чтобы следующий не «дочистил»: export function mapMcpServers в agents.ts:210 — рантайм в контрактном файле, попавший туда раньше правила. Это не прецедент к расширению. И сборка литерала в трёх describe — принятый осознанно шум: помощник ради неё был бы переусложнением.

Обратная сторона: решение про дом потолков размазанность убирает — шесть литералов из трёх плагинов съезжаются в один именованный модуль. С тремя правками выше пункт 6 суммарно уменьшает дублирование, а не добавляет.

Проверка по SOLID, DRY, KISS, чистой архитектуре

ТребованиеКак решение ему отвечает
S — одна ответственностьДержится. Shortfall отвечает на один вопрос: почему ответ короче, чем есть. Сборка, формат и запись в журнал — три отдельные маленькие обязанности, а не один «менеджер неполноты». Возврат «страница плюс её метка» — не две ответственности, а один ответ со своим признаком целостности: ровно как listing() отдаёт перечень вместе с complete.
O — открыт для расширенияС честной оговоркой. Новый вид меры потребует правки санитайзера: на границе доверия иначе нельзя — валидировать неизвестную форму невозможно. Значит объединение на границе закрыто намеренно, и добавление вида есть сознательная правка контракта, а не бесплатное расширение. Это надо назвать, а не выдавать за открытость.
L — подстановкаДержится по построению, и это главный довод за разворот зависимости. Старый transcript выведен из нового ((await readPage()).entries), поэтому для прежних потребителей он не может повести себя иначе, чем раньше. Две независимые реализации такой гарантии не дают — только обещание синхронности.
I — разделение интерфейсовСлабое место, называю прямо. AgentHistory растёт: шесть методов, из них два необязательных. Необязательность спасает реализатора — он берёт, что может, — но интерфейс копит пары «метод и его честный близнец». Дробить его сейчас значило бы ломать живой контракт ради чистоты; принимаем накопление осознанно и следим, чтобы третья пара потребовала разговора, а не появилась по инерции.
D — инверсия зависимостейДержится. Хост зависит от абстракции AgentHistory, плагины её реализуют. Помощники живут на плагинной стороне и зависят от типа-контракта, а не наоборот; обратного направления — чтобы контракт знал о поведении — не появляется нигде.
DRYДержится после правок: четыре источника дублирования убраны, пятый принят осознанно и записан. Шесть литералов-потолков съезжаются в один дом. Суммарно дублирования становится меньше, чем было до пункта.
KISSДержится, и решение убрало две сущности: поле complete (выводится из метки) и состояние «тело не читалось» (призрак похороненного наследования). Массив вместо одиночки — сложнее, но вынужденно: два рода недостачи в одном чтении доказаны кодом.
Правка по KISS: наружу отдаём одну функцию — «предупреди о недостаче», — а форматирование прячем внутрь модуля. Три экспорта там, где потребителю нужен один, — лишняя поверхность.
Чистая архитектураДержится. Контракт — порт: чистые данные, ни одной зависимости от реализаций. Плагины и потребители хоста — адаптеры по разные стороны. Граница между слоями проходит по вопросу «зовёт ли это хост».
Оговорка на будущее: слова журнала у плагина и у сканера — разные предложения разных слоёв. Их нельзя «унифицировать»: плагин говорит о своём чтении, хост — о своей укладке.

Шов внешнего яруса — что выкопано

Срезание чужих полей — доктрина, а не недосмотр. В шве стоит тест с прямым текстом: «An unknown extra field in facts drops at the boundary — the answer is rebuilt from known fields only, never passed through» (hostDispatch.test.ts:329-341). Он шлёт лишнее поле и требует, чтобы его не было в ответе. Значит внесение метки в белый список — сознательная правка контракта, а не починка. Тест при этом останется зелёным: его поле так и осталось чужим.

  • Метод добавляется ровно в одном месте — объединение в protocol.ts:222. Строкового разбора на хосте нет: прокси передают литералы. Рантайм-охрана уже универсальная — default в госте бросает на неизвестный метод.
  • Истории лимитер не касается — он живёт только в канале уведомлений.
  • Скан выбирает поля вручную (historyScan.ts:119-128), так что метка не утечёт в схему индекса сама собой. Но и не доедет: лог обязан читать её явно.
  • Флаг гостя выводится тогда и только тогда, когда метод есть на объекте — дословно как у listing. Явный отказ в case оставляем зеркально: у битого гостя иначе будет TypeError вместо внятного отказа.
  • Готового валидатора юниона в дереве нет — собираем из трёх местных образцов: цикл с отказом на первом плохом элементе, литеральная строгость дискриминанта, мера через проверку на конечное число. Порядок величин (returned ≤ total) не валидируем: это дело свидетелей, а лишняя строгость откажет законной странности.
  • Гонки в шве нет: корреляция вызовов по идентификатору, кэша между открытиями нет, времена чтений в ключи индекса не входят. Встреча двух чтений одного файла — присущая семантика, покрыта правилом какого чтения.

Свидетели

  • Санитайзер пропускает метку → красный, если срезает. Главный: без него всё остальное зелено при потерянной метке.
  • Точная форма на проводе — три сценария: одиночный bytes, одиночный turns, и turns + parts вместе.
  • Санитайзер отказывает: неизвестный kind · не-число в мере · пустой массив.
  • Мутация «вернуть complete рядом» → красный. Иначе кто-нибудь вернёт «удобное поле».
  • Парный метод зовут оба потребителя — и браузер, и прокси внешнего яруса: точек вызова транскрипта две, не одна.
