## СЕГОДНЯ — разбор на главном потоке окна

```
            ┌─────────────────── webview окно (ГЛАВНЫЙ ПОТОК) ───────────────────┐
            │                                                                      │
 скан ──────►  historyScan: батчи ×16 ──► describe() / content()                  │
            │      60 сессий / 297 MB               │                             │
 клик ──────►  transcript(offset,limit) ────────────┤                             │
            │                                      ▼                             │
            │   ┌───────────── плагин (claude/codex/kimi) ───────────┐            │
            │   │  fs.readFile (8MB cap)        ← текст приходит     │            │
            │   │        │                        целиком в main     │            │
            │   │        ▼                                           │            │
            │   │  split + JSON.parse ←── ⚠ БЛОКИРОВКА UI: сотни ms  │            │
            │   │  (parseTurns / parseRollout / parseWire)            │            │
            │   │        │                                           │            │
            │   │        ▼           opencode: sqlite.query → rows   │            │
            │   │   turns[] {role,text}                                │            │
            │   │   opencode: sqlite.query → rows → JSON.parse          │            │
            │   │            part.data/message.data ПОСТРОЧНО (join)     │            │
            │   └────────────────────────────────────────────────────┘            │
            └──────────────────────────────┬───────────────────────────────────────┘
                                           │ IPC (текст)
                                           ▼
                          Rust (Tauri пул): project_fs_read_file / sqlite
                          — диск и SQL уже вне webview; PARSE — нет
```

Один поток делает всё: кадры UI И чтение ответов И разбор.
Каждый transcript-клик перечитывает + перепарсивает файл целиком.

## НОВОЕ — plugin-owned операции, API-агностик воркер

            ┌─────────── webview окно (ГЛАВНЫЙ ПОТОК — только кадры и оркестрация) ───────────┐
            │                                                                                │
 скан ──────►  historyScan (батчи ×16)                                                       │
 клик ──────►  transcript                                                                │
            │      │                                                                      │
            │      ▼                                                                      │
            │   ┌── плагин — ВЛАДЕЛЕЦ ЗНАНИЯ: что читать, как звать ──┐                      │
            │   │   fs.readFile / sqlite.query (IO остаётся в main)   │                      │
            │   │        │ bounded payload: текст/байты/rows + ИМЯ ОПЕРАЦИИ  │                      │

            │            │ turns[] (+summary для JSONL)                                       │

## СРАВНЕНИЕ

|                        | СЕГОДНЯ                        | НОВОЕ                                |
|------------------------|--------------------------------|--------------------------------------|
| Разбор JSONL/rows      | главный поток — ⚠ лаг          | worker — main свободен              |
| Кадры при скане        | замораживаются (сотни ms)      | парсерная блокировка снята; frame gaps / clone — замером |
| Формат агентов         | у каждого плагина (в main)     | там же, но в воркере — владелец тот же |
| Воркер                 | нет                            | 1 runtime + entry на плагин         |
| Кто что знает          | плагин знает, main исполняет   | плагин ВЛАДЕЕТ (формат/код); воркер ИСПОЛНЯЕТ код, не зная формата/API |
| Копирование данных     | —                              | +structured clone (цена, названа)   |
| Wall-time суммарный    | база                           | может чуть вырасти (клон) — замер   |
| transcript-перечитывание | есть (на main, каждый клик)  | остаётся (уже вне main) — кэш после замера |
| external-плагины       | парс уже в их iframe-realm     | без изменений; свой worker — потом  |

Одной строкой: сегодня один поток делает всё; после — плагин ВЛАДЕЕТ
операцией (формат, вход, dispatch, код разбора), worker ИСПОЛНЯЕТ
статически встроенный plugin-owned код в своём realm, не зная его формата
или API; главный поток только рисует и читает. Цена — копия при передаче;
проверка — замер до/после (свидетель №1 постановки).
